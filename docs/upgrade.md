# Upgrading from 0.7.1

The release notes are generated by release-please into `CHANGELOG.md`; this guide holds the upgrade steps that a changelog line cannot carry.

## Layers: take only what you need

The plugin has three layers. Each one is opt-in and builds on the previous one.

| Layer | What you do | What it needs |
| --- | --- | --- |
| **Core**: `AiWriterAction` + providers | Nothing. Update the package. | Nothing: no plugin registration, no migrations, no tables. It behaves like 0.7.1. |
| **`usageTracking()`**: ledger, deduplication, **AI Writer usage** statistics | Register the plugin and call `->usageTracking()`. | Publish and run the package migrations. `authorizeViewStatistics()` decides who sees the page and the metric widgets. |
| **`controls()`**: credits, abuse protection, **AI Writer controls**, credits indicator | Add `->controls()` to the same plugin. | `usageTracking()` on the same panel (otherwise the panel throws a clear configuration error), the same migrations, and `authorizeManage()` for administrators. |

### Only the action, no migrations

Update and keep generating. A project that never registers the plugin and never runs the migrations keeps working: no table is read or written, no page, route or render hook is added, and failures show the short generic message of the [two-layer error messages](#error-messages-changed).

Register the plugin only when you want panel permissions (`authorizeUseAi()`); with no module enabled it still adds nothing but the permission checks.

### Turn on `usageTracking()` and `controls()`

```php
use PdroLucas\FilamentAiWriter\AiWriterPlugin;

AiWriterPlugin::make()
    ->usageTracking()
    ->controls()
    ->authorizeViewStatistics(fn ($actor, $panel): bool => $actor->can('view-ai-usage'))
    ->authorizeManage(fn ($actor, $panel): bool => $actor->can('manage-ai'));
```

```bash
php artisan vendor:publish --tag=filament-ai-writer-migrations
php artisan migrate
```

Both modules use the same four migrations (`000001` to `000004`), published together. The package never migrates for you and never touches your user table. If you already run a beta build with credits (`000003`) or abuse protection (`000004`), follow the [cutover steps](integration.md#credits-deployment-and-recovery) first.

Each module can be switched off again with `false` or a `Closure`: nothing is deleted, and turning it back on resumes the stored settings, balances and audit.

## Authorization and closures

- Closures of `authorize*()` and `scope()` are resolved **by parameter name or type, not by position**: `$actor` (also `$user`), `$panel`, `Authenticatable` and `Panel`. `fn () => ...` and `fn (Panel $panel, $actor) => ...` both work.
- `authorizeUseAi()`, `authorizeViewStatistics()` and `authorizeManage()` called **without an argument** mean `true`: they grant the permission to every authenticated actor of the panel. Pass a `Closure` or `false` to restrict them. Left unset, use is allowed, and statistics and administration are denied.
- Statistics are **panel-wide**. A tenant `scope()` does not filter them, so give `authorizeViewStatistics()` only to accounts that may see every tenant's metadata (see the corrected [tenant example](integration.md#panel-setup-and-a-scoped-actor-directory)).

## Plugin API conventions

The fluent API was standardized before release: setters take `bool|Closure` or `string|Closure` and are evaluated when used, each setter has a matching getter, and every feature has its own prefix (`usageTracking()`, `controls()`, `statisticsPage()`, `controlsPage()`, `creditsPage()`, the per-page navigation setters, `creditsIndicator*()`, `requireReason()`, `usersTab()`). The public API of `AiWriterAction` from 0.7.1 is unchanged. See the README's [Pages and navigation](../README.md#pages-and-navigation).

## For people who tested the PR #21 build (`feat/plugin-release`)

Migration `000002` was edited in place: the audit reason became nullable. Databases migrated from that build need `php artisan migrate:fresh` (or recreating the package tables) before using this version.

## Behavior changes you may notice

### Error messages changed

People who generate text now get either a specific denial they can act on (disabled, blocked, credits exhausted with the renewal date, frequency, concurrency, failure pause, unusable output) or, for technical failures, a short generic message with a reference code. The full detail goes to the log (`AI Writer generation failed.`, same `reference`) and appears in the notification only for `authorizeManage()` users; without a registered plugin nobody sees it. Alert on that log line if you want to hear about storage or provider problems.

### Texts, dates and currency

Every text comes from `lang/vendor/filament-ai-writer` overrides or the package's `en` and `pt_BR` files. Dates follow your Filament date format and timezone (also per user), where the plugin used to fix `M j, Y H:i:s` and the application timezone. Costs show the code from `filament-ai-writer.currency`. See [Messages, translations and formats](integration.md#messages-translations-and-formats).

### Native look

Plugin screens no longer ship CSS. If you restyled `.ai-usage*` classes, the `--ai-writer-controls-gap` variable or `.ai-controls` / `.ai-controls-nav`, those hooks are gone; use your Filament theme. If you published views, republish or compare them: `usage-styles.blade.php` and `controls/styles.blade.php` were removed, and the statistics page now renders native widgets and filters. The remaining public hooks are listed in [Customize presentation](integration.md#customize-presentation).

### Navigation

Pages share a translatable **AI Writer** navigation group by default, not a root menu entry. Place, rename or cluster them with the plugin's navigation setters.
